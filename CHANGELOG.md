# Changelog

Versions, newest first. 0.12.0 is a breaking change.

- 0.13.1 fixes `stall-check.sh` stopping under dash (the Linux `/bin/sh`) when the transcript is missing or unreadable: it now prints the note and carries on. CI also installs zsh, which the feedback test needs.
- 0.13.0 adds the `ordo:feedback` skill (drafts a feedback or issue report with a list of all your settings and their level, redacts it, prints it in full and sends it only after your explicit yes; also shows or clears your usage log) and an opt-in local usage log of the plugin's own skills, agents and scripts (`ordo usage_log: on`, off by default, 13th key, see Usage log and feedback in the README); the usage summary counts runs, failed, aborted, not allowed, denied (auto mode) and cancelled. A Monitor launch of an own script counts as a run when it starts (its outcome is not reported, shown as "started through Monitor"). Nothing is sent automatically: the hooks make no network call.
- 0.12.0 is a breaking rename: the plugin is now `ordo` (marketplace `ordo-marketplace`), so skills and agents are `ordo:<name>` and the `CLAUDE.md` lines read `ordo <key>: ...`. It also adds the private-terms leak check in `scripts/check-publish.sh` and `scripts/export-public.sh`, which copies the shipping files to an empty directory and checks the copy. This plugin was renamed from roles in 0.12.0. To migrate: uninstall the old plugin under its old name, install ordo as described in the README, and change the first word of each switch or setting line in your `CLAUDE.md` to `ordo`; agent and skill names now start with `ordo:`.
- 0.11.0 adds the `stall_watch` switch (the twelfth, see Switches) and watching of background helpers (see Watching helpers in the README): the `ordo:workflow` skill watches every background helper or job, reports progress and stalls, and carries four brief rules for helpers; the script `plugins/ordo/skills/workflow/stall-check.sh` does the checks. New keys `watch_check_minutes`, `watch_report_minutes`, `watch_check_by`.
- 0.10.0 adds on/off switches (see Switches in the README) for the guard hook, the git rules, the eval cost budget and each helper, review, qa and acceptance step, an `ordo: switched off:` line at session start, a README light-mode example, a verify-first and DISPUTED answer for wrong review findings, one shared source for the reviewers' rules block (`shared/findings-and-rounds.md`, copied by `scripts/sync-rules-block.sh`), and no model names in skill text: rounds 4 and 5 name the helper's normal model and the stronger ones from the environment text.
- 0.9.0 adds the `workflow` skill (the whole of the old CLAUDE.md §5, plus the never-rebase and `ordo:goal` lines), prints its load line from the SessionStart hook at every startup, resume and compact, and removes §5 from `claude-md/CLAUDE.md`, which is now optional extras (§1-4, §6). The goal-discipline spec is amended to match.
- 0.8.0 adds goal discipline: the `goal` skill, a SessionStart goal hook (see Goal hook in the README), category tags and the round rule in `code-reviewer`, `qa` and `po`, the plain-question rule in `ba`, `po` and `consult-panel`, and `LESSONS.md` as the retro destination. Six new evals (`side-request-now-or-park`, `question-plain-one-rec`, `round2-wording-not-blocking`, `round2-keep-still-blocks`, `round4-asks-user`, `round2-history-auto-runs`). `~/.claude/CLAUDE.md` and `claude-md/CLAUDE.md` are unchanged.
- 0.7.0 adds the Bash guard hook (see Safety hook in the README), the `eval-plan` and `retro` skills, and `scripts/eval-audit.sh`.
- 0.6.2 makes `ba` check the global `~/.claude/CLAUDE.md` for reader settings even without a project CLAUDE.md.
- 0.6.1 adds the full-read rule to `dev`, `qa`, `code-reviewer` and `po`.
- 0.6.0 adds the `reader` agent and lets `ba` dispatch it for large reading sets (see Reading settings in the README). Reader-covered files appear under `## Read` marked `(via reader)`.
- 0.5.0 makes `ba` read every named file in full and list what it read under `## Read`.
- 0.4.0 renames `business-analyst` to `ba` and `product-owner` to `po`; their role text is unchanged. Update any CLAUDE.md that names the old agents.
- 0.3.0 renames `senior-dev` to `dev` and `senior-qa` to `qa`; the roles keep their senior persona. Update any CLAUDE.md that names the old agents.
- 0.2.0 also gives `senior-dev` and `senior-qa` (now `dev` and `qa`) shell rules: commands longer than the foreground limit run in the background, no wait loop without a failure exit, and the macOS traps (no `timeout`, BSD `sed -i ''`).
